== Phase 1 : Debut de Session (15 minutes max)

=== 1.1 Presentation du contexte

L'agent reprend le contexte depuis :

* PROMPT_REPRISE.adoc (mission de la session)
* INDEX.adoc (etat EPICs, roadmap)
* SESSIONS_HISTORY.adoc (historique des sessions recentes)
* SESSION_PROCEDURE.adoc (procedure de travail)
* SESSION_CHECKLIST.adoc (checklist)

=== 1.2 Cadrage de la tache

L'agent doit specifier exactement :

1. **EPIC concerne** (ex: EPIC V-9, EPIC Y, EPIC W, etc.)
2. **Type de travail** (implementation, debug, test, documentation, revue)
3. **Objectif tangible** (ex: "terminer EPIC V-9.1", "ecrire 3 sous-taches")
4. **Delai estimé** (ex: "1-2h", "3-4 sessions")

=== 1.3 Plan de travail

L'agent propose un plan de travail concret :

1. Quels fichiers vont etre modifies?
2. Quelles tâches Gradle vont etre ajoutees/modifiees?
3. Quels tests vont etre ajoutes/modifyes?
4. Quelle documentation doit etre mise a jour?

**Regle d'or** : 1 fichier a la fois, modifier, valider, puis passer au suivant.

== Phase 2 : Execution (variable)

=== 2.1 Modifier un fichier

Pour chaque fichier a modifier :

1. **Lire le fichier en entier** (read tool)
2. **Analyser le contexte** (architecture, conventions, patterns)
3. **Proposer la modification** (edit ou write)
4. **Attendar confirmation utilisateur** (sauf si permission donnée)
5. **Compiler/apres modification** (./gradlew build -x test)
6. **Valider les tests** (./gradlew test, si permission)

=== 2.2 Ajouter un fichier

1. **Creer le fichier** (write tool)
2. **Respecter les conventions** (naming, structure, documentation)
3. **Compiler apres creation** (./gradlew build -x test)
4. **Ajouter les tests si necessaire**

=== 2.3 Revue de code

L'agent doit toujours :

1. Verifier la **coherence architecturale** (clean architecture, patterns)
2. Verifier la **qualite du code** (Kotlin idiomatic, pas de commentaires superflus)
3. Verifier la **cobverture de tests** (JUnit5 + Cucumber)
4. Verifier la **documentation** (JavaDoc, AsciiDoc)

* Ajouter la session terminee (date, EPICs, livrables)

Mettre a jour `.agents/TEST_COVERAGE_ANALYSIS.adoc` :

1. Creer le dossier `.agents/backup/Y{annee}-sessions-{plage}/`

== Gestion des Secrets (regle absolu)

* **NE JAMAIS** afficher de tokens, passwords, API keys dans le terminal
* **NE JAMAIS** utiliser `echo`, `cat`, ou toute commande qui affiche des secrets
* **NE JAMAIS** modifier des fichiers gitignores sans sauvegarde (`git check-ignore <fichier>`)

**Checklist securite** :

* [ ] Aucun token en argument de commande
* [ ] Aucun secret dans les logs
* [ ] `grep -r "TOKEN\|SECRET\|PASSWORD\|API_KEY\|gho_\|ghp_"` executé
* [ ] Retirer les faux-positifs si necessaire

== Anti-patterns a eviter

| # | Anti-pattern | Symptome | Correction |
|---|--------------|----------|------------|
| 1 | **Session trop longue** | > 50 messages ou > 3 fichiers paralleles | Splitter. 5x20min > 1x2h. |
| 2 | **PROMPT_REPRISE fantome** | configuration/.agents/PROMPT_RERISE.adoc pas mis a jour | L'etape 2 est obligatoire |
| 3 | **Archive vide** | Le fichier de session cree mais sans contenu utile | Template obligatoire |
| 4 | **Portefeuille fantome** | INDEX.adoc liste des projets qui ne sont plus gouvernes | Mettre a jour le portefeuille |
| 5 | **Secrets dans logs** | Tokens/passwords visibles dans le terminal | Interdit formellement |
| 6 | **Edit sans sauvegarde** | Modification d'un fichier gitignores sans backup | Sauvegarder avant |
| 7 | **Trop d'agents** | Multiples agents specialises avant projet stable | Attendre 10+ sessions |
