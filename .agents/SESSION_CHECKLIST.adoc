== Session Procedure

=== Debut de Session

* [ ] Mission injectee par opencode (configuration/.agents/PROMPT_REPRISE.adoc)
* [ ] Lire INDEX.adoc (regles absolues + etat EPICs)
* [ ] Lire AGENT.adoc (regles absolues)
* [ ] Lire SESSION_PROCEDURE.adoc (procedure de travail)
* [ ] Charger les fichiers ESSENTIALS si l'EPIC est concernee

=== Fin de Session (6 etapes obligatoires)

==== Etape 1 : Archive session

* [ ] Creer l'archive LAZY : `.agents/sessions/{N}-{type}-{sujet}.adoc`
* [ ] Template obligatoire : contexte, actions, commandes, resultats, lecons
* [ ] Ne pas laisser le fichier vide

==== Etape 2 : Mission N+1

* [ ] Mise a jour `configuration/.agents/PROMPT_REPRISE.adoc` — Mission N+1 (max 70 lignes)
* [ ] Ne pas depasser 70 lignes
* [ ] Ecrire Concis, pas de vague

==== Etape 3 : Dashboard N+1

* [ ] Mise a jour INDEX.adoc
* [ ] Ajouter la session terminee (date, numeros, EPICs concernees)
* [ ] Mettre a jour etat EPICs (progression, blocages, termines)
* [ ] Mettre a jour portefeuille (ajouter/supprimer projets)

==== Etape 4 : Historique

* [ ] Mise a jour `.agents/SESSIONS_HISTORY.adoc`
* [ ] Ajouter entrée : date, session N, EPICs, livrables
* [ ] Ne pas oublier les sessions sans EPIC (debug, refactoring, etc.)

==== Etape 5 : Tests

* [ ] Mise a jour `.agents/TEST_COVERAGE_ANALYSIS.adoc` (si tests modifies)
* [ ] Ajouter: nouveaux tests, modifications, suppression
* [ ] Mettre a jour couverture, stats, benchmarks

==== Etape 6 : Archivage mensuel

* [ ] Si session multiple de 10 (N % 10 == 0) :
* [ ] Creer le dossier `.agents/backup/Y{annee}-sessions-{plage}/`
* [ ] Y copier INDEX, SESSIONS_HISTORY, COMPLETED_TASKS_ARCHIVE
* [ ] Tronquer fichiers actifs aux 10 dernieres sessions
* [ ] Mettre a jour INDEX.adoc avec localisation de la nouvelle vague

* [ ] Si fichiers EAGER cumules > 500 lignes (wc -l) :
* [ ] Meme procedure que ci-dessus (backup + troncature)


== Etape 7 — Synchronisation backlog (détail obligatoire)

=== Détail — Synchronisation backlog (detail obligatoire)

*Recurrentement mal appliquee* : la table de statut final est mise a jour
mais les *sections detaillees* des EPICs gardent des marqueurs perimes
(`🟡 a faire`, `⏳ A FAIRE`, `A PLANIFIER`, `EN PAUSE`) alors que l'INDEX
marque `✅ TERMINE`. Faux positif qui fausse l'ouverture de session suivante.

Portee de la synchronisation (a executer a CHAQUE cloture de session) :

. *Table de statut final* — si une US/EPIC est termine cette session,
  marquer `✅ TERMINE (S-NNN)` dans la table aggreee.
. *Sections detaillees des EPICs* — pour CHAQUE US/EPIC termine cette
  session, mettre a jour la colonne `Statut` dans le tableau detaille de
  l'EPIC (pas seulement la table aggreee). Marqueurs a remplacer :
  `🟡` → `✅`, `⏳ A FAIRE` → `✅ TERMINE (S-NNN)`, `A PLANIFIER` →
  `✅ TERMINE` ou `✅ CADUQUE`, `EN PAUSE` → `✅ TERMINE`.
. *En-tetes de section* — si l'EPIC est termine, remplacer `🟡 EPIC X
  (Session NNN — Cadrage/EN PAUSE/a planifier)` par `✅ EPIC X (Session
  NNN — TERMINE)`.
. *Paragraphes de statut* — mettre a jour le paragraphe recapitulatif
  sous la table de statut final (versions publiees, sessions de
  reference, dependencies cloturees).
. *TODO.adoc* (si present) — cocher les items termines `[ ]` → `[x]`,
  ajouter les nouveaux items decouverts.

Verification post-synchronisation (obligatoire avant de marquer l'etape 7 OK) :

----
grep -n "🟡\|⏳\|À FAIRE\|À PLANIFIER\|EN PAUSE\|à planifier\|à faire" BACKLOG.adoc
----

Si la commande retourne des matches pour des EPICs/US *deja termines*
(selon l'INDEX), la synchronisation n'est *pas* terminee — corriger les
marqueurs et re-verifier.

*Note* : cette verification ne s'applique qu'aux EPICs/US *termines*. Un
marqueur `🟡` pour un EPIC *reellement en cours* ou *a planifier* est
legitime et ne doit pas etre supprime.

== Gestion des Secrets

* [ ] Aucun token/password/API key dans le code ou les logs

* [ ] Retirer les faux-positifs (ex: `tokenRef: $TOKEN` n'est pas un leak)
