== Constats P2/P3 audités (7)

=== S2 (P2) — Auto-registration libre `gradle_*`

`TaskDiscoveryRegistrar` enregistre toute tâche Gradle découverte comme tool
`gradle_*` dans le `ToolRegistry`. Un agent LLM peut appeler n'importe quelle
tâche Gradle découverte (ex. `gradle_publishToMavenCentral` qui pousse des
artefacts). Pas d'allowlist sur les tasks découvertes.

*Site* : `src/main/kotlin/codebase/koog/discovery/TaskDiscoveryRegistrar.kt`
(référence à vérifier).
*Risque* : publication accidentelle, exécution de tâches destructrices
(`clean`, `purge`, wrapper updates).
*Stratégie* : allowlist des tâches découvertes (pattern `build|test|check|
compile|assemble|jar|publishToMavenLocal|tasks|help` + project:task form),
deny-list second ride (`publishToMavenCentral`, `publishAggregation*`,
`clean`, `purge`, `wrapper`, `bootstrap`). Reuse pattern US-1/US-2
ExecShellTool/ExecGradleTool.

=== S3 (P2) — `edit_file`/`write_file` sans garde de taille

`ToolRegistry.executeAction("write_file")` (L119-126) et `"edit_file"`
(L128-139) écrivent le contenu sans vérifier la taille. Un LLM peut écrire
un fichier de 100MB → OOM + saturation disque.

*Sites* :
* `contracts/vibecoding/registry/ToolRegistry.kt:125` (`file.writeText(content)`)
* `contracts/vibecoding/registry/ToolRegistry.kt:138` (`file.writeText(updated)`)
*Stratégie* : `MAX_WRITE_CHARS` const (ex. 1_000_000 = ~1MB), check
`content.length > MAX_WRITE_CHARS` → `IllegalArgumentException("write_file
content exceeds ${MAX_WRITE_CHARS} chars")` avant `writeText`. Idem pour
`edit_file` (`newString.length` + `updated.length`). ~4 unit.
*Note* : `read_file` a déjà `MAX_OUTPUT_CHARS` (L117 `file.readText().take
(MAX_OUTPUT_CHARS)`) — pattern à mirror.

=== C1 (P1 mais hors scope P1) — `contains("failed")` faux positif + `expectedOutput` jamais comparé

`TaskResultVerifier.verify` (TaskResultVerifier.kt:17-43) heuristique
fragile :
* L31 `combined.contains("failed")` matche `0 failed tests` (réussite) →
  `TaskVerdict.FAILED` faux positif.
* `expectedOutput` (GradleTask N0 S-064, StepVerifier) n'est jamais comparé
  au stdout réel — le contrat de vérification N0 est inutilisé.

*Site* : `src/main/kotlin/codebase/koog/planning/TaskResultVerifier.kt`
*Stratégie* : refonte `TaskResultVerifier` — (1) heuristique améliorée :
  `failed` doit être précédé d'un contexte négatif (`BUILD FAILED`,
  `tests failed`, `compilation error`), pas `0 failed` ; (2) comparaison
  `expectedOutput` quand non-default `"BUILD SUCCESSFUL"` : si stdout
  `contains(expectedOutput)` → SUCCESS, sinon FAILED. ~10 unit.
*Risque* : backward compat — tests existants utilisent `"BUILD SUCCESSFUL"`
default. Préserver l'heuristique actuelle comme fallback quand
`expectedOutput` est default.

=== C4 (P2) — `GradleTaskArgsMapper` flags cassés

`GradleTaskArgsMapper.buildCommand` (L9-20) construit `"$taskName $flags"`
où `flags = "--key value --key2 value2"`. `ExecGradleTool.executeBlocking`
passe `cmd` comme un seul `task` arg à `ProcessBuilder("./gradlew", args.task)`
(L51). Mais `ExecGradleTool.validateGradleTask` (US-2 S-186) split par `\\s+`
et valide 1er token vs `GRADLE_TASK_ALLOWLIST` + reste vs `GRADLE_ARG_ALLOWLIST`
(`--\\w+`).

Le flag `--key value` (2 tokens : `--key` + `value`) — `value` ne matche pas
`--\\w+` → **rejeté deny-by-default**. Les flags avec valeur sont cassés.

*Site* : `src/main/kotlin/codebase/koog/discovery/GradleTaskArgsMapper.kt:18`
*Stratégie* : `buildCommand` doit produire une chaîne compatible avec
`validateGradleTask` — soit `--key=value` (1 token match `--\\w+=\\S+` ? non,
pattern est `-P[\\w.]+=\\S+`), soit étendre `GRADLE_ARG_ALLOWLIST` pour
accepter `--\\w+ \\S+` (pair flag+value). Décision à prendre en US.
~6 unit.

*Priorité* : P3 — la duplication ne cause pas de bug, juste dette technique.

=== C7 (P3) — `Plan remaining tasks` négatif possible

*Site* : `src/main/kotlin/codebase/koog/VibecodingGraph.kt:464`

~1 unit.
*Priorité* : P3 — trivial, 1 ligne.

== Décisions architecturales

=== Décision 1 — Allowlist sur tasks découvertes (S2)

Pattern US-1/US-2 (allowlist deny-by-default + deny-list second ride) appliqué
à `TaskDiscoveryRegistrar`. Allowlist des préfixes de tâches sûres +
project:task form. Deny-list second ride (`publishTo*`, `clean`, `purge`,
`wrapper`, `bootstrap`).

=== Décision 2 — Garde de taille write_file/edit_file (S3)

`MAX_WRITE_CHARS = 1_000_000` (~1MB) const dans `ToolRegistry`. Check avant
`writeText` → `IllegalArgumentException`. `edit_file` check aussi
`updated.length`. Pattern `read_file` `MAX_OUTPUT_CHARS` (déjà existant L117).

=== Décision 3 — TaskResultVerifier refonte (C1)

Backward compat : heuristique actuelle conservée comme fallback. Nouveau
chemin prioritaire : si `expectedOutput != "BUILD SUCCESSFUL"` (custom),
comparer `stdout.contains(expectedOutput)` → SUCCESS sinon FAILED. Heuristique
`contains("failed")` raffinée : regex `(?<!0 )failed` (failed non précédé de
`0 `) ou exclusion `0 failed`. ~10 unit.

=== Décision 4 — Cleanup doc INSERT-X (C3)

Suppression pure des commentaires stale L60-84. Zéro test impact.

=== Décision 5 — GradleTaskArgsMapper flags (C4)

Extension `GRADLE_ARG_ALLOWLIST` pour accepter `--\\w+ \\S+` (pair flag+value
2 tokens) en plus de `--\\w+` seul. OU `buildCommand` produit `--key=value`
(si `GRADLE_ARG_ALLOWLIST` étendu à `--\\w+=\\S+`). Décision : étendre
`GRADLE_ARG_ALLOWLIST` à `--\\w+(?:=\\S+)?` (flag seul ou flag=value) ET
accepter `--\\w+ \\S+` (flag value séparés). ~6 unit.

  passait avant.
