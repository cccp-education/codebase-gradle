== Contexte

Le pilote a demandé de **tester l'environnement** de l'EPIC avant de générer
le moindre deck : valider le câblage `OllamaInstanceScanner` →

== Constats d'audit (avant code)

. Les tests `OllamaInstanceScannerTest` et `OllamaLlmProviderTest` ne testent
  qu'**un seul port CI fixe** (`11466`) via `assumeTrue`/`EnabledIf`. Aucun test
  ne scanne la **plage autorisée entière** `11437..11465`.
. `LlmProviderResolver.resolveOllamaInstances()` retombe, sans
  `OLLAMA_SCAN_PORTS`/`OLLAMA_POOL_PORTS`, sur `OllamaInstanceFactory.create()` :
  29 instances déclarées sans probe réseau. **Vérifié : ce n'est pas un bug** —
  c'est un contrat documenté (`epic_v6_resolver.feature` : « available without
  probing the network », scénario `@factory` = 29 instances). Corriger ce défaut
  aurait cassé un contrat BDD et rendu la suite non-hermétique. **Option A
  retenue** : préserver le contrat, ajouter le test d'intégration gated.
. Probe terrain : **28/31** ports vivants (`11438`, `11449`, `11450` down),
  `gemma4:31b-cloud` servi partout. Ollama Cloud proxifie tout modèle cloud
  même non listé dans `/api/tags` (appel `gpt-oss` sur un port gemma-only OK).

== Livrable 2 — Bug P1 découvert par le test d'intégration

Le test d'intégration réel **a révélé un bug de production** :

* Symptôme : appel pool → `dev.langchain4j.exception.RateLimitException`
  propagée, test FAILED (2/2 → 1/2).
* Message réel Ollama Cloud :
  `you (cherolivcontact) have reached your monthly usage limit, upgrade for
  higher limits` (compte du port 11437, premier de la rotation).
* Cause : `OllamaPoolKeyAdapter.isQuotaError` (ligne 106) ne matchait que
  `quota`, `rate limit`, `exceeded`, `429` — **pas** `usage limit`. La branche
  `else -> throw e` propageait l'exception au lieu de rotationner.
* Impact : **tout appel pool échouait** dès que le premier port tombait sur un
  compte épuisé, alors que 27 autres instances étaient saines. Le pool perdait
  sa raison d'être (résilience par rotation).

[CAUTION]
====
Le bug était invisible pour la CI : les tests unitaires injectaient des messages
`"quota exceeded"` (déjà matchés), et les tests d'intégration ne ciblaient qu'un
port CI sans quota réel. Seul un **appel réel sur la plage réelle** pouvait le
révéler — exactement le trou de couverture identifié.
====

== Méthode (baby-step DDD/TDD strict)

. **RED** — test unitaire `callWithRotation should rotate on real Ollama Cloud
  monthly usage limit` (message réel Ollama Cloud copié verbatim) → FAILED.
. **GREEN** — ajout du motif `message.contains("usage limit", ignoreCase=true)`
  dans `isQuotaError` → 11/11 `OllamaPoolKeyAdapterTest` PASSED.
. **REFACTOR** — re-run du test d'intégration réel : 2/2 PASSED (rotation
  depuis 11437 épuisé vers un port sain, 4 occurrences du message limit dans
  les logs, issue OK).
