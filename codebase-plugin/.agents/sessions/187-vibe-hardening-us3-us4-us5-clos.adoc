== Lecons apprises

* Default parameter Kotlin : un paramètre default peut référencer un
  paramètre précédent seulement — déplacer `llmTimeoutMs` AVANT
  `stepVerifier` pour propager le timeout au StepVerifier via default.
* Bug S-088 DuplicateStepDefinition : préfixer toutes les steps par "vibe
  hardening" évite les doublons avec VibecodingSteps (glue partagée
  `codebase.scenarios`).
* Test d'intégration replan timeout : le timeout LLM est récupérable
  (clearError + retry), donc l'itération suivante écrase lastToolResult.
  Assert terminaison而非 contenu précis — le comportement testé est "ne
  hang pas", pas "surficie le timeout dans le dernier résultat".
