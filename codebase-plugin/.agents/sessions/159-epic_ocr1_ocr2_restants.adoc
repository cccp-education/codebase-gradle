== Items livrés

=== OCR-1 HTTP 429 detection + rotation auto (backlog ligne 596)

* `GeminiKeyPool.markRateLimited(instance)` / `isRateLimited(instance)` — instance skippée par `nextInstance()` jusqu'au `resetUsage()`
* `GeminiVisionProvider` ouvert (`open class`, `override open suspend fun`), accepte `GeminiKeyPool` optionnel dans le constructeur
* Détection "429" / "Too Many Requests" dans le `catch` de `processImage` → `pool.markRateLimited(instance)`
* Fallback best-effort : si toutes les instances sont rate-limited, retourne la première non rate-limited
* Tests : 4 unitaires `GeminiKeyPoolTest` + 2 unitaires `GeminiVisionProvider429Test` + 3 Cucumber `@epic_ocr_1`

=== OCR-1 env var mapping GEMINI_API_KEY_1..N (backlog ligne 594)

* `GeminiPoolFactory.fromKeys(keys, model, idPrefix)` — construit un `GeminiKeyPool` depuis une liste explicite
* `GeminiPoolFactory.fromEnvVars(env, model)` — lit `GEMINI_API_KEY_1..N`, skip les vides, ordre 1→N garanti
* Câblage `OcrTask.geminiApiKeys` + `resolveGeminiProvider(model)` + `resolveGeminiPool(model)` — pool construit depuis DSL ou `System.getenv()`
* Tests : 11 unitaires `GeminiPoolFactoryTest` + 3 fonctionnels `OcrTaskPoolTest` + 2 Cucumber `@epic_ocr_1`

=== OCR-1 multi-compte (backlog ligne 597)

* `GeminiMultiAccountPool` — 1 `GeminiKeyPool` par compte Google, rotation entre comptes
* `GeminiMultiAccountPool.fromEnvVars(env)` — lit `GEMINI_ACCOUNT_{accountId}_API_KEY_{keyIndex}`, skip vides
* `markRateLimited` / `isRateLimited` / `resetUsage` délégués au bon sous-pool
* `GeminiPoolFactory.fromKeys` enrichi avec `idPrefix` pour IDs uniques entre comptes
* Tests : 8 unitaires `GeminiMultiAccountPoolTest` + 4 Cucumber `@epic_ocr_1`

=== OCR-2 fallback Tesseract (backlog ligne 605) — boundary harmonisé

*Decision* : Tesseract est un OCR documentaire sans IA → appartient à **codex-gradle (Brooklyn N2, READ+RAG)**, pas codebase (Queens N1, LLM).

* **codex-gradle** : `codex.ocr.OcrEngine` interface (`process(OcrRequest): OcrResult`) + `codex.ocr.TesseractOcrEngine` (CLI tesseract via ProcessBuilder, best-effort ne jette pas)
* **codex-gradle** : 5 tests JUnit5 `TesseractOcrEngineTest` PASS, `publishToMavenLocal` 0.0.1
* **codebase-gradle** : `codebase.koog.llm.CodexOcrEngineAdapter` wrap `codex.ocr.OcrEngine` → `VisionProvider` (boundary adapter)
* **codebase-gradle** : `TesseractOcrProvider` supprimé (plus de duplication), `OcrTask` fallback chain : Gemini → Ollama → `CodexOcrEngineAdapter(TesseractOcrEngine())`
* Tests : 2 fonctionnels `OcrTaskTesseractFallbackTest` + 2 Cucumber `@epic_ocr_2`

== Boundary architecturale

* **codex-gradle (Brooklyn N2, READ+RAG)** : détient les engines OCR documentaires (sans IA) — `OcrEngine` + `TesseractOcrEngine`
* **codebase-gradle (Queens N1, LLM)** : orchestre la fallback chain LLM via `CodexOcrEngineAdapter` — Gemini → Ollama → Tesseract
* Le boundary est strict : codex expose les engines OCR purs, codebase les adapte dans `VisionProvider`
