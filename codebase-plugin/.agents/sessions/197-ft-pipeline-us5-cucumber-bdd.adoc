== Leçons

. *BDD pur sur domaine* — les 4 scénarios pilotent le domaine pur via
  fakes/stubs ([FakeFineTuner], [StubRegistryClient],
  [FakeFineTuningLlm], [StubPromptBuilder]) sans invoquer de tâche Gradle
  ni émettre d'appel réseau. Pattern identique à VibeHardening2/Subgraph
  — la BDD domaine valide le contrat fonctionnel sans la mécanique
  d'exécution Gradle.
. *FIFO queues pour LLM itératif* — `FakeFineTuningLlm` expose des
  FIFO queues pour `propose`/`validate` afin de piloter le cycle
  itératif `FineTuningGraph` (1 propose + 1 validate par itération).
  Le scénario "Cycle itératif converge" envoie 2 propose + 2 validate
  (re-propose après score < threshold), le scénario "Validation seuil
  dès la 1re" envoie 1 propose + 1 validate.
. *39e `CucumberTaskSpec`* — le borough codebase-plugin atteint 39
  cucumber runners dédiés (pattern S-082). `cucumberTestFineTuning`
  hérite du `testFast` (timeout ≤ 8 min défaut, exécution 9s).
