== Leçons

* Une option de validation stricte doit être explicite et désactivée par défaut pour ne pas casser les workflows existants.
* Les exceptions levées par une Gradle task doivent être des `GradleException` pour un affichage propre dans le build.
* Réutiliser les steps Cucumber existants (V-9.15) via `@Before("@epic_v_9_15 or @epic_v_9_16")` évite la duplication tout en isolant les features.
* Corriger une régression pré-existante découverte pendant la session est préférable à la laisser dans le build (zéro régression).
