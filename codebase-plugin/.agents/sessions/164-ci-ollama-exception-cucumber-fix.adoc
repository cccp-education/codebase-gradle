== Objectif

Documenter l'exception CI/CD pour les tests d'intégration GitHub Actions
(modèle léger `qwen3:0.6b` sur ports dédiés 11466-11467, hors plage rotation
11437-11465 et hors ports protégés 11434-11436). Corriger 2 bugs Cucumber
préexistants qui bloquaient `testFast` (PR gate CI) depuis les sessions 158/159.

== Contexte

Travail hérité non commité post-session 163 (README architecture). La session
163 avait livré la réorganisation README plugin/consommateur, mais un travail
CI/CD parallèle (cache Docker Ollama + ports CI + adaptation tests d'intégration)
était resté en working tree non commité.

Conflit identifié : la règle AGENTS.adoc « Aucun autre modèle ni port »
interdisait `qwen3:0.6b` et ports 11466-11467. Décision utilisateur : assouplir
la règle pour la CI/CD uniquement (tests d'intégration GitHub Actions), jamais
pour le vibecoding local/production.

=== 4. Fix Cucumber préexistant — DuplicateStepDefinitionException

*Bug* : `Ocr1PoolSteps.poolUsageReset()` (session 159) collide avec
`PoolSteps.\`pool usage reset\`` car `EpicY4CucumberRunner` et
`EpicVPoolCucumberRunner` gluent tout `codebase.scenarios` (incluant
sous-package `ocr`).

*Fix* : step renommé `the pool usage is reset` →
`the Gemini key pool usage is reset` dans `Ocr1PoolSteps.kt` + `ocr.feature`
ligne 61. Sémantiquement plus précis (reset GeminiKeyPool, pas OllamaPool).

=== 5. Fix Cucumber préexistant — Assertion stale 5 modèles

*Bug* : `epic_v_pool.feature` scénario "Pool full capacity" attendait
"5 distinct authorized models" mais `AUTHORIZED_MODELS` ne contient que 2
modèles depuis l'alignement AGENTS.adoc session 158 (`gpt-oss:120b-cloud` +
`gemma4:31b-cloud`).

*Fix* : feature mise à jour "5 modèles" → "2 modèles" + titre scénario aligné.

== Leçons

. *Bug préexistant non détecté* : `testFast` échouait depuis la session 159
  (DuplicateStepDefinition) mais n'avait pas été remarqué — la CI GitHub Actions
  n'était pas active. Importance de valider `testFast` après chaque modification
  de steps Cucumber.
. *Assouplissement règle CI* : la contrainte AGENTS.adoc sur les modèles/ports
  est légitime pour le vibecoding production, mais doit céder devant la réalité
  d'un runner CI gratuit (RAM limitée, pas d'auth cloud). L'exception documentée
  préserve la règle générale tout en rendant la CI fonctionnelle.
. *Baby steps DDD/TDD/BDD* : 1 fichier à la fois, compilation entre chaque,
  test ciblé sur les runners impactés avant `testFast` complet. Méthodologie
  respectée.
