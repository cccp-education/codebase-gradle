Root cause : `computeEmbedding` retourne le vecteur **avec brackets**
(`joinToString(",", "[", "]")`) et `StoreStatements.updateEmbedding`
re-encapsule `'[$vec]'` → littéral `'[[-0.016...]]'` → cast pgvector
échoue, erreur avalée silencieusement par R2DBC (Result jamais
inspecting). Fix baby-step TDD : `updateEmbedding` strip les brackets
(`trim('[', ']')`) — contract documenté KDoc, +1 test RED → GREEN
(9/9 StoreStatementsTest). La migration verbatim S-199 a hérité du
bug (codex computeEmbedding retournait les nombres sans brackets ;
search binding `$1` exige les brackets, update inline ne doit en
porter qu'une paire).
