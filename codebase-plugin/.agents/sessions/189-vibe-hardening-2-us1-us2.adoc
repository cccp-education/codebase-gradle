== Leçons

* Allowlist deny-by-default pour tasks découvertes : la deny-list n'est
  qu'un second ride pour les composed commands qui passent l'allowlist
  (ex. `:plugin:publishToMavenCentral` matche project:task allowlist
  puis deny-list catch). Pour les noms purs (`clean`, `purge`,
  `wrapper`), c'est l'allowlist qui rejette — message "not in
  allowlist", pas "denied pattern". Tests initiaux mal conçus sur ce
  point, corrigés.
* Changement comportemental US-1 sécuritaire mais majeur : les tasks
  métier du plugin (vibecode, qualityGate, etc.) ne sont plus
  auto-enregistrées. C'est le comportement attendu — un agent LLM ne
  doit pas piloter la boucle agentique elle-même via tools découverts.
