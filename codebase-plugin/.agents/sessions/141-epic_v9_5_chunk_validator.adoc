  blank checksum, checksum mismatch (sha256 du content vs champ checksum),
  weight négatif, weight > 1.0, weight aux bornes 0.0 et 1.0.
- Run : 8 failed / 2 passed — rouge attendu (logique de validation absente).

=== Baby step 3 (unit) — implémentation complète ChunkValidator

- Validation champs non vides (id, sourceFile, content, sourceLines,
  checksum).
- Cohérence checksum : `sha256(content)` doit égaler `chunk.checksum`.
- Bornes weight : `0.0 <= weight <= 1.0`.
- Retourne `ValidationResult(valid = errors.isEmpty(), errors)`.
- Run : 10/10 PASS ✅.

== Leçons

- L'anti-duplication systématique avant de coder un item backlog évite
  du travail mort : V-9.1/V-9.2/V-9.4 étaient déjà couverts par EPIC Y.
- ChunkValidator est un bon exemple de baby-step TDD pur : contrat
  trivial, 10 tests, implémentation < 25 lignes, 0 dépendance (pas de
  DB, pas de réseau, pas de Spring).
- Le pattern Cucumber "1 runner par EPIC + 1 world + 1 steps" se
  duplique proprement sans toucher aux runners existants.
- Pour V-9.3 ScanAgent, attention à ne pas dupliquer
  `IngestGovernanceTask.collectGovernanceFiles` (hardcoded 7 paths) :
  remplacer par un scanner récursif du dossier `.agents/` sans casser
  les tests `IngestGovernanceTaskTest` (5 tests PASS existants).
