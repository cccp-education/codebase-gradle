== Atelier 1 : Vision

=== QQOQCP

[cols="2,5"]
|===
| Qui | L'agent vibecoding (VibecodingGraph koog) + le LLM qui exécute des tâches
| Quoi | Une capacité programmatique de zoom contextuel : classifier le niveau requis, charger le contexte au bon niveau de granularité, transiter dynamiquement entre niveaux
| Où | Dans `codebase/koog/autofocus/` — package dédié dans codebase-plugin N1
| Quand | Avant chaque exécution de tâche dans VibecodingGraph. Node 0 (classify) + Node 1 (zoom) insérés avant buildContext
| Comment | `AutofocusLevel` enum (4 niveaux) + `AutofocusClassifier` (heuristique regex + fallback LLM) + `ContextZoomer` (ranking graph.json) + `AutofocusStack` (LIFO push/pop)
| Pourquoi | Le gap identifié session 073 : l'IA associe (RAG+Graphify) mais ne zoome pas. Sans autofocus, le LLM traite tout au même niveau → noyade dans le bruit → décisions stratégiquement aveugles
|===

=== Product Vision Board

==== Target Group
- VibecodingGraph (consommateur primaire) — insère Node 0 + Node 1 dans le graphe koog
- VibecodingTask (consommateur secondaire) — bénéficie d'un contexte filtré par niveau
- EPIC X (Plan Multi-Step) — chaque étape du plan peut avoir son propre niveau de zoom
- EPIC Y (Agentic Literature Compiler) — ingestion au bon niveau de contexte

==== Needs
- Classifier automatiquement le niveau d'abstraction requis par une intention
- Filtrer le contexte augmenté selon le niveau (x1=8000 tokens → x1000=500 tokens)
- Naviguer entre niveaux pendant l'exécution (zoom-in → exécuter → pop → décider)
- Revenir au niveau stratégique après chaque zoom-in

==== Product
- `AutofocusLevel` : 4 niveaux (BIG_PICTURE, ARCHITECTURE, MODULE, IMPLEMENTATION)
- `AutofocusClassifier` : classification heuristique (regex, 0 token LLM) + fallback LLM (~5 tokens)
- `ContextZoomer` : filtrage du contexte par niveau, ranking Aider-like sur graph.json
- `AutofocusStack` : pile LIFO pour naviguer entre niveaux
- `AutofocusNode` : nœud koog intégré dans VibecodingGraph

==== Value
- Le LLM ne se noie plus dans le contexte — il adapte sa focale
- Les décisions stratégiques (x1) ne sont plus polluées par le bruit d'implémentation (x1000)
- Le feedback loop V-6 zoome automatiquement sur la cause racine d'une erreur
- 5ème verbe ZOOMER dans la taxonomie workspace

==== Competitors
- RAPTOR (Stanford, 2024) : arbre de résumés multi-niveaux — inspire AutofocusContextTree
- Aider Repo Map : ranking sur graphe de dépendances — inspire ContextZoomer
- LangChain Contextual Compression : filtrage post-recherche — inspire la passe IMPLEMENTATION
- Aucun ne fait l'aller-retour dynamique en boucle agentique (zoom + pop + rezoom)

=== Business Model Canvas (simplifié)

- *Key Partners* : graphify-gradle (N0, fournit graph.json), MEMPHIS workspace-bom (contrats N0)
- *Key Activities* : classification niveau → filtrage contexte → navigation LIFO → intégration koog
- *Key Resources* : AUTOFOCUS_CAPABILITY.adoc (spécification), graph.json (1572 nœuds), pgvector (RAG)
- *Value Proposition* : Le LLM passe de "je lis tout" à "je zoome sur ce qui compte"
- *Customer Relationships* : API interne (VibecodingGraph), pas d'interface utilisateur direct
- *Channels* : package `codebase.koog.autofocus`, intégré dans le graphe koog existant
- *Customer Segments* : VibecodingGraph (N1), EPIC X (plan multi-step), EPIC Y (compiler agentique)
- *Cost Structure* : ~20 pts de développement, 0 token LLM pour la classification heuristique
- *Revenue Streams* : N/A (interne, Apache 2.0)

=== Contrat d'interface

[source,kotlin]
----
interface AutofocusClassifier {
    fun classifySync(intention: String, buildOutput: String? = null): AutofocusLevel?
    suspend fun classify(intention: String, buildOutput: String?, llmProvider: LlmProvider): AutofocusLevel
}

interface ContextZoomer {
    fun zoom(target: AutofocusLevel, context: AugmentedContext, intention: String): AugmentedContext
}

interface AutofocusStack {
    fun push(level: AutofocusLevel)
    fun pop(): AutofocusLevel
    fun currentLevel(): AutofocusLevel?
    fun isEmpty(): Boolean
}
----
